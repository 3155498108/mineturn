# 劫掠兽客户端冻结修复

日期：2026-10-12。对应 `DEEPSEEK_RAVAGER_FREEZE_HANDOFF.md`。

交接定位到 `RavagerBattleMixin.aiStep` 入口取消是正确的，但不能将所有 `>= 0` 改为 `> 0`：同步计时的 `-1` 表示原版接管，`0` 表示战斗接管但当前计时结束，正数表示还有剩余计时。getter 返回同步的零也是必要行为，否则会读到客户端实体事件留下的原版旧计时。

原版 `Ravager.aiStep` 首先调用父类。父类最终执行 `LivingEntity.aiStep` 中的位置、身体旋转和头部旋转插值。取消整个方法使服务器移动包的插值无法推进，这与用户报告的显示不移动相符；不是服务器战斗寻路本身被此方法停止。

修复：在战斗接管期间，客户端先同步原版眩晕/吼叫字段，再执行父类 `aiStep`，保留攻击动画实时时钟；继续跳过 Ravager 自身的原版计时、吼叫伤害和破坏树叶逻辑。服务器保持原有冻结，眩晕/吼叫仍由 AV 驱动，结束战斗后恢复原版计时。

扩展已有 `ravagerStunRoarAvAndCleanup` 回归：直接调用原版入口不会消耗战斗眩晕和吼叫计时；同步零不能退回实体事件留下的旧计时；离场后原版计时恢复。此服务器测试不替代客户端视觉验收。

客户端待复测：普通追击的位置与朝向、盾挡眩晕后的吼叫与恢复移动、攻击动画，以及离场后正常行动。

验证：389 项必需 GameTest 全部通过，完整构建成功，`git diff --check` 通过。日志：`build/ravager-client-interpolation.log`。产物：`build/libs/mineturn-1.0.0.jar`，SHA256 `50E2C3D8E421A0691A6FB1D4F2BE0D904A3B0DF35992A75DC60A139DD20F77D3`。
